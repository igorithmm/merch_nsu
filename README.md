# Мерч НГУ — учёт товара

Локальное приложение для продавца магазина университетского мерча: остатки по
моделям и размерам, продажа в один тап, поставки, журнал действий, контроль
непробитых в кассе продаж, заявки покупателей и отчёты для заказа новой партии.
Работает и с одеждой, и с сувенирной продукцией.

Работает без интернета и без установки зависимостей — нужен только Python 3.9+.
Все данные лежат в одном файле `data/merch.db` рядом с программой.

## Установка на рабочий компьютер

Один раз ставим Python, дальше всё делается двойным кликом — терминал не нужен.

**1. Поставить Python.** Скачайте с [python.org/downloads](https://www.python.org/downloads/).
При установке на Windows на первом же экране поставьте галочку
**«Add python.exe to PATH»** — это важно. На macOS Python обычно уже стоит.

**2. Скачать программу.** На странице репозитория: зелёная кнопка **Code** →
**Download ZIP**. Распакуйте в удобную папку, например `C:\merch` — так, чтобы
файл `run.py` лежал прямо в ней.

**3. Запустить.** Двойной клик по ярлыку в этой папке:

* Windows — **`Запустить.bat`**
* macOS — **`Запустить.command`**

Откроется браузер с приложением. Если Python ещё не установлен, ярлык сам
покажет окно с подсказкой и откроет страницу загрузки.

Чтобы запускать с рабочего стола: правый клик по ярлыку → «Отправить» →
«Рабочий стол (создать ярлык)». На macOS — перетащите файл в Dock.

### Как закрыть

Кнопка **«Завершить работу»** в шапке, рядом с именем продавца. Данные
сохраняются сразу после каждой операции, так что закрывать можно в любой
момент — ничего не потеряется. Повторный двойной клик по ярлыку просто откроет вкладку заново, а
не запустит вторую копию программы.

### Первый раз — посмотреть на примере

При первом запуске база пустая, и на вкладке «Остатки» будет кнопка
**«Заполнить примером»**. Она заведёт несколько моделей с продажами, чтобы сразу
посмотреть карточки, журнал и отчёты. Кнопка работает только в пустой базе —
поверх ваших данных пример не запишется. Когда наиграетесь, заведите свои товары
на вкладке «Товары», а лишние уберите в архив.

### Запуск из терминала

Нужен редко, но работает:

| Команда | Что делает |
| --- | --- |
| `python run.py` | обычный запуск |
| `python run.py --port 9000` | другой порт (если 8765 занят — свободный подберётся сам) |
| `python run.py --no-browser` | не открывать браузер |
| `python run.py --demo` | залить пример данных |

## С чего начать

1. **Настройки → Продавцы** — добавьте имена тех, кто стоит за прилавком.
   Выбранное в шапке имя попадает в каждую строку журнала; при смене продавца
   приложение переспросит, чтобы операции не ушли на чужое имя.
2. **Товары → Новая одежда** (или «Новый сувенир») — заведите модель: тип
   (толстовка), цвет (фиолетовая), принт (большая печать), материал, цену и
   размерный ряд. Там же — наименование в 1С и ссылка на товар в
   интернет-магазине store.nsu.ru.
3. **Остатки → «Поставка партии»** на карточке — впишите, сколько штук пришло
   по каждому размеру. Это и есть первичный ввод остатков.
4. Дальше просто работайте: кнопка **−** под нужным размером → «Продажа».

Кнопка **?** в шапке открывает справку по всем разделам приложения и отдельный
гайд по цветам с образцами.

## Категории товара

Каждый товар относится к одной из двух категорий:

* **Одежда** — есть размерный ряд и материал. Готовые ряды: российские 42–56,
  буквенные XXS–3XL и OS (один размер, для шоперов и подобного). Свой ряд
  вписывается через запятую;
* **Сувенирная продукция** — кружки, ручки, значки: размеров нет, на карточке
  один общий счётчик.

## Как менять остаток

Остаток меняется только кнопками **−** и **+** под числом. Каждая открывает меню
с причиной операции и полем «сколько штук» — само число не нажимается, случайно
списать товар нельзя:

| Кнопка | Причины |
| --- | --- |
| **+** | Поставка · Возврат от покупателя |
| **−** | Продажа · Брак · Случайный клик (исправление) |

На карточке одежды есть «Поставка партии» — ввод сразу по всем размерам одной
накладной, и «Пересчитать» для инвентаризации.

Любую операцию можно отменить: кнопкой «Отменить» во всплывающем уведомлении
или «Откатить» в журнале. Откат возвращает остаток и оставляет обе записи в
журнале — история не переписывается.

## Наименование в 1С и непробитые продажи

В карточке товара есть поле **«Наименование в 1С»**. Пока оно пустое, стоит
флажок **«Не заведён в 1С»**, и каждая продажа такого товара помечается как
**не пробитая в кассе** — так бывает, когда оплату приняли раньше, чем товар
можно провести через кассу.

Вкладка **«Не пробито»** показывает все такие продажи: сколько их, на какую
сумму, по каким товарам и **в чью смену** они прошли. Когда чек пробили,
нажмите «Пробито» у записи или «Пробито всё» у товара. Заполнение
наименования в 1С само по себе флажки не снимает — это разные вещи: товар
заведён в номенклатуре, но чек ещё не пробит.

### Пересорт

Бывает, что конкретный размер или конкретный сувенир из-за пересорта нужно
пробивать под другим наименованием 1С. Кнопка **«Пересорт в 1С»** на карточке
открывает список размеров, где для каждого можно вписать своё наименование и
примечание.

Размер с пересортом помечается синей рамкой и значком **1С** на плитке, а на
карточке появляется метка «Пересорт: N». Перед списанием меню причин показывает
крупную подсказку, под каким именем пробивать товар, — и то же имя сохраняется
в журнале и в выгрузке CSV, так что при сверке видно, что и как ушло.

Если у размера задан пересорт, продажа считается пробиваемой и в список
«Не пробито» не попадает, даже когда у самого товара наименование в 1С пустое.

## Стоп-продажа

Товар можно временно снять с продажи — целиком или отдельными экземплярами.

* **Весь товар** — флажок «Снят с продажи целиком» и причина в карточке товара
  (кнопка «Карточка»). Карточка становится полосатой, у неё метка с причиной,
  а пункт «Продажа» в меню недоступен.
* **Отдельные экземпляры** — кнопка «Отметки размеров», поле «снято, шт».
  Например, из пяти толстовок размера L одна испачкана: ставим 1, и продать
  можно будет только четыре. На плитке появляется метка **−1**, а меню перед
  списанием показывает, сколько доступно к продаже.

Отметка привязана к штукам, а не ко всему размеру, поэтому она уходит сама,
когда товара не остаётся: списали испачканную толстовку как брак — счётчик
снятых обнулился, и новая партия придёт уже чистой.

**Приход, возврат, брак и коррекции работают всегда** — запрет касается только
продажи. Чип «Снято с продажи» в фильтрах показывает всё, что сейчас недоступно.

## Желания

Вкладка **«Желания»** — что спрашивали покупатели, но чего не было в наличии:
товар, дата обращения, контакты клиента и имя продавца. У каждой заявки есть
статус: «Ждёт», «Клиенту сообщили», «Закрыта». Закрытые прячутся из списка, но
остаются в истории и в выгрузке CSV.

## Подсветка остатков

* **красным** — 0 шт, закончилось;
* **жёлтым** — мало, **только у сувенирной продукции**: у одежды одна-две штуки
  размера это норма, а не повод для тревоги, поэтому жёлтой подсветки там нет;
* **зелёным** — товара с запасом, и у одежды, и у сувенирки.

Пороги настраиваются отдельно для одежды и сувенирки на вкладке «Настройки».
Фильтр **«Заканчивается»** показывает только модели, где что-то на нуле или
сувенирки осталось мало.

Поиск работает мгновенно по названию, цвету, принту и материалу: «толстовка
фиолет» находит нужное. Фокус в поле поиска — клавиша `/`.

Цветная полоска слева от названия подбирается по слову в поле «Цвет»: около
сотни оттенков от молочного и морской волны до фуксии и баклажана, с любым
окончанием слова. Полный список с образцами — в справке (кнопка **?** в шапке,
раздел «Гайд по цветам»). Незнакомый цвет — просто серая полоска, на учёт это
не влияет.

Остатки показываются **плитками** (крупные кнопки по каждому размеру) или
**списком** — по одной строке на товар: название, цена, общий остаток и все
размеры компактными ячейками. Списком на экран помещается вдвое больше товара;
клик по ячейке открывает то же меню причин, только сразу с обеими группами —
«списать» и «добавить». Переключатель — рядом с сортировкой, выбор запоминается.

Список можно **сортировать по цене** — «сначала дешёвые» или «сначала дорогие»;
выбор тоже запоминается.

Отдельная строка **«Размеры»** фильтрует одежду по размерам, и выбрать можно
сразу несколько — например, 42 и 44. Тогда на карточках останутся только эти
размеры, а рядом с ценой будет видно, сколько штук в выбранных размерах и
сколько всего. Сувенирка при таком фильтре скрывается — у неё размеров нет.
Снять выбор — кнопкой «Все размеры» или общим «Сбросить».

## Отчёты

Период задаётся кнопками (7/30/90 дней, год) или парой дат, можно ограничить
категорией и типом товара.

* **Что продаётся** — штуки, выручка, остаток и на сколько дней его хватит при
  текущем темпе.
* **Какие размеры вымываются первыми** — только по одежде: доля размера в
  продажах против его доли в остатке. Числовые и буквенные ряды считаются
  раздельно. Если синяя полоса заметно длиннее серой — этого размера в
  следующей партии нужно больше.
* **Пора заказывать** — позиции, которые продаются и вот-вот кончатся, с
  оценкой количества на месяц вперёд.
* **Лежит без движения** — товар с остатком, который не продавался дольше
  порога из настроек, и сколько денег в нём заморожено.

## Журнал действий

Все продажи, поставки, возвраты, брак и коррекции — когда, кто, что, сколько
штук и на какую сумму. Туда же попадают события справочника: заведение товара,
правка карточки, отправка в архив. Фильтры по периоду, типу операции, продавцу,
плюс поиск по тексту. Кнопка «История» на карточке товара открывает журнал
сразу по этой модели.

Ненужную запись можно **удалить в корзину**. Если она ещё учтена в остатках,
приложение предупредит и предложит сначала откатить операцию — тогда товар
вернётся на склад. Из корзины запись можно вернуть обратно, а через 60 дней
она удаляется сама.

## Данные и бэкап

Вся база — один файл `data/merch.db`. Чтобы сделать копию, просто скопируйте
папку `data` (при остановленном приложении). Выгрузка в CSV для Excel —
на вкладках «Отчёты», «Журнал» и «Настройки».

## Как устроено

```
Запустить.bat     ярлык для Windows — двойной клик
Запустить.command ярлык для macOS — двойной клик
run.py            запуск: поднимает локальный сервер и открывает браузер
app/db.py         SQLite: схема, миграции, остатки, журнал действий
app/api.py        бизнес-логика: товары, операции, отчёты, экспорт
app/server.py     HTTP-сервер и JSON-API
app/demo.py       генератор примера данных
web/              интерфейс: index.html, style.css, app.js
```

Внешних библиотек нет — только стандартная библиотека Python и обычный
JavaScript в браузере.
